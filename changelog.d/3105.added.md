- **Library format specification and converter contract (#3105, #3106)** — `docs/LIBRARY_FORMAT.md` specifies the library, symbol and footprint files byte for byte, with conformance fixtures, so external converters can write libraries Signex opens unchanged. `docs/LIBRARY_CONVERTER_CONTRACT.md` and its JSON Schema define how Signex runs a library converter: the `describe` and `library` commands, a progress stream, a per-item loss report and exit codes. The schema file alone is licensed MIT OR Apache-2.0.
- **Footprints carry their own 3D models (#3107)** — attaching a STEP model to a footprint embeds it in the footprint file, compressed, so a footprint copied or moved on its own keeps its model; identical models in one file are stored once. Libraries that keep models in a `step/` folder still open, and each such footprint embeds its model the next time it is saved; the folder is never deleted.
- **Library tools on the command line (#3109, #3111, #3116)** — `signex-cli library check` validates a library folder (rows, references, embedded models and the exact file form; `--strict` also fails on warnings), `signex-cli library render` writes each symbol and footprint as SVG or PNG, and `signex-cli library textconv` shows embedded model data as one line in `git diff`.
- **Imported libraries (#3110, #3112, #3113, #3114)** — a library converter's output is written as a git-tracked library under `~/Signex/Libraries/<name>` and mounted for all projects. Re-importing updates it as one new commit and deletes only what the earlier import wrote; it is refused while the library has unsaved edits or uncommitted changes, and a failed update restores the library. The Library Browser shows a library's licence and source, and Messages names a library another one needs that is not open. Imports are started from File ▸ Import ▸ Library… (#3117).
