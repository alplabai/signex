- **Saving a component row in a large library is several times faster (#416)** — an insert, edit, delete or version bind on a 50k-row library now takes about 0.25–0.45 s instead of 1.2–2.4 s, and about 80–150 ms instead of 300–350 ms at 10k rows. Rows are shared between the in-memory copy and the edit being saved, so only the edited row is copied; when memory holds Signex's own last write, only the edited row is checked again and unchanged rows reuse their encoded line; and the git commit hashes the file once. The file is still written whole through the atomic temp-file write and committed once per edit, a stale edit is still refused, and the first edit after the library is loaded or changed on disk, or one that adds a table or a column, still takes the full write, which re-checks every row and reads the file back.
