- **A version-control commit now records the bytes that were saved or restored (#859)** — "Save X" and "Restore X" commits used to read the file when their worker ran, so an edit from another program, or a History restore, that landed in between was committed under the save's label. The save hands its bytes to the commit (the file's LFS pointer for a Git LFS path), and a restore commits the revision it wrote. If the file has changed again by then, git still reports it as modified rather than clean. A save made while another commit of the same file runs is queued behind it with its own bytes. A commit of an older save never replaces or follows a newer one. A restore is held back only by a commit of that same file that has not captured its bytes (a primitive-editor save, for example), not by any commit in the project.
