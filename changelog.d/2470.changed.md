- **Exports no longer replace a file without asking, and stay out of `.git` (#2470)** — `export_board_report` and `export_board_pdf` run from `signex-cli` (headless or attached) refuse a `path` where a file already is unless `overwrite=true` is given, and answer once the file is written. The one export rule now refuses, for both board commands and for the notebook exports (the `export_notebook_pdf` command, the Export PDF dialog and the measurement lane's CSV export): a Signex document as the target, a target inside a `.git` folder (in any case), and on Windows a name ending in a dot or a space or holding `:`. `fabrication_outputs` refuses an output folder inside `.git` too.
