- **Library symbol updates keep the sheet copy and its version in step (#950)** — "Update from library", Personal-mode auto-apply at open and the Team Library Updates dialog all replace the embedded symbol and stamp the instances' library version together, so an applied update no longer reappears as drift or as a pending update. There is one apply path: a worker reads the library's current symbol and each instance's row fresh (through the library the row itself lives in), and the result lands as one undo step per shared symbol (none for the silent open-time apply). Every instance shares one embedded copy, so an apply covers every placed instance of a selected symbol: unticking an instance of a selected symbol does not exclude it, and the dialog offers one checkbox per shared symbol. At open, a symbol is auto-applied only when every placed instance of it has a readable Personal-mode row that still binds it; if a stale instance is Team-mode its stale instances go to the dialog, and if an unreadable, missing, unmounted, re-bound or Team sibling blocks it, nothing is applied and Messages names that reference. Each instance is decided from its fresh row: a row that binds the symbol is stamped with the version read; a re-bound row, a missing row and an unreadable library each get their own Messages line ("version not stamped") and keep their stamp. If a row moved on after the version the user approved, the whole symbol is held back (no copy, no stamps) with one summary line naming the moved and the left-behind instances, and the next scan offers it again; other symbols in the same Apply still apply. A refused update (a connected pin would vanish) leaves both untouched and says why. A completion for a sheet that was closed, reloaded or renamed meanwhile is dropped with a Messages line, and Apply on a sheet that is no longer open keeps its pending record.
