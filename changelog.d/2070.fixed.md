- **Applying a library update no longer overwrites a part you edited meanwhile (#2070)** — a footprint, Manufacturer or MPN changed while Apply (or "Update from library") was running now keeps your edit, on every unit of a multi-unit part, and Messages names the part and field it left alone (no line when you typed the row's new value). The unit you edited has its base advance to the row, so your edit reads as an override and a later row change raises a conflict; a sibling unit that was skipped only because of your edit keeps its old base, so its drift stays flagged. The part's version moves with the update. A multi-unit part gets one Messages line per field, naming the edited unit. A part moved to another row meanwhile (Change Component) is skipped whole (every unit of it), with a Messages line; when it is re-linked to a row that binds the same `lib_id`, the shared embedded symbol copy is still refreshed, because that copy is shared by every part of the `lib_id`.
