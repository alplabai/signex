- **Pin references and checked wires and buses from the command line (#2199)** — a point operand also takes `<designator>.<pin>` (`R1.2`, `U1.VCC`), which is that pin's tip on the sheet the edit targets, off the grid or not: `signex-cli run demo.snxprj place_wire --arg start=R1.2 --arg end=C1.1 --save`. A wire from operands is checked before it lands and refused, with the reason, when its path also touches another pin, label, junction, sheet pin or wire, joins two nets that carry different names (`allow_merge=true` allows it), crosses a symbol body, runs diagonally, or leaves an end connected to nothing (`allow_open=true` allows it). A bus is checked the same way: orthogonal segments, no body crossing, no dangling end, no other bus run, entry or bus-name label pulled in, and no merge of two differently named buses without `allow_merge`. `dry_run=true` (`--dry-run`) reports the result without changing anything. An accepted run answers with both ends (the reference and the point it resolved to), the segments, the net or bus and its pins or names, and the names it merged. `allow_merge` is explained in `docs/CLI.md`.
- **Placements take an optional `document` (#2199)** — the label, power port, junction, no-connect, no-ERC, text, wire, bus, line and rectangle commands run on the named sheet (an id or a path) when given, and never on the active tab; an unknown, unloaded or read-only document is refused with its reason. They stay reachable by an agent only through `apply_edits`.
